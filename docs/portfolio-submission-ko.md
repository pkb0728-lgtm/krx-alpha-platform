# 포트폴리오 제출 가이드

이 문서는 KRX Alpha Platform을 GitHub 포트폴리오로 보여줄 때 어떤 순서로
설명하면 좋은지 정리한 한국어 가이드입니다.

## 한 문장 소개

한국 주식 데이터를 수집하고 품질을 검증한 뒤, 시장 국면, 종목 점수,
리스크 필터, 자동 스크리너, 백테스트, 페이퍼트레이딩, 텔레그램 알림,
대시보드까지 연결한 설명 가능한 투자 의사결정 보조 플랫폼입니다.

## 면접에서 보여줄 실행 순서

면접 답변 자체는 [면접 답변 가이드](interview-guide-ko.md)를 함께 참고하면
좋습니다.

1. 환경 확인

```powershell
python main.py doctor
```

2. API 연결 확인

```powershell
python main.py check-apis --save
```

3. 하루 운영 작업 미리보기

```powershell
python main.py run-daily-job --universe large_cap --lookback-days 180 --kis-paper-candidates --telegram-dry-run
```

4. 대시보드 실행

```powershell
streamlit run src/krx_alpha/dashboard/app.py
```

5. 테스트 실행

```powershell
pytest
```

## 후보가 0개일 때 설명하는 방법

후보가 0개라는 결과는 오류가 아닐 수 있습니다. 이 프로젝트는 무조건
매수 후보를 만드는 도구가 아니라, 조건이 부족하면 쉬는 판단을 내리는
리스크 우선 시스템입니다.

예를 들어 다음과 같은 경우 후보를 만들지 않습니다.

- 신뢰도나 스크리너 점수가 기준보다 낮음
- 단기 변동성이 높음
- 위험 점수가 약함
- 시장 국면 데이터가 부족하거나 비우호적임
- 최종 판단이 `watch`, `hold`, `blocked` 상태임

면접에서는 이렇게 설명하면 좋습니다.

```text
이 시스템은 매일 종목을 추천하는 것이 목적이 아닙니다.
데이터와 리스크 기준을 통과한 경우에만 사람이 다시 검토할 후보를 만들고,
조건이 부족하면 후보 없음으로 남기는 보수적인 의사결정 보조 도구입니다.
```

## 거래 0회와 평가금액을 설명하는 방법

페이퍼 포트폴리오나 워크포워드 검증에서 거래 수가 0회로 나올 수 있습니다.
이 경우는 계산 오류라기보다, 해당 기간에 `buy_candidate` 신호가 없어서
가상 매매를 실행하지 않았다는 뜻입니다.

대시보드에는 이 결과를 검산할 수 있도록 다음 항목을 표시합니다.

- `체결 거래 수`: 거래장 데이터에서 `status=filled`인 행 개수
- `최종 평가금액`: 현금 + 보유 주식 평가금액
- `가상 수익률`: 최종 평가금액 / 시작 가상 현금 - 1
- `워크포워드 거래 수`: 각 검증 구간의 `trade_count` 합계
- `매수 후보 신호 수`: 각 검증 구간의 `exposure_count` 합계

면접에서는 이렇게 설명하면 좋습니다.

```text
페이퍼 포트폴리오의 최종 평가금액은 임의로 만든 숫자가 아니라
현금과 보유 주식 평가금액을 더해 검산합니다.
거래가 0회인 경우에는 매수 후보 신호가 없어서 현금 100%로 대기한 상태이며,
워크포워드도 각 검증 구간의 trade_count 합계로 거래 수를 확인합니다.
```

KIS 모의투자 후보 화면에 보이는 큰 총평가금액은 KIS 모의계좌에서 조회한
잔고 기준 값입니다. 이 값은 후보 수량 계산에만 사용하며, 페이퍼
포트폴리오의 가상 시작금액과는 별개입니다.

## 실제 주문을 넣지 않은 이유

이 프로젝트는 취업 포트폴리오와 개인 분석 도구 목적입니다. 그래서
한국투자증권 API는 모의투자 토큰, 잔고 조회, 후보 계산까지만 연결하고
실제 주문 API 호출은 구현하지 않았습니다. 대신 `manual_order_plan` 산출물로
예상 수량, 예상 금액, 기준 가격, 공시/뉴스/유동성/시장 국면 확인 항목을
정리합니다.

이 설계는 다음 이유로 안전합니다.

- 실수로 실제 매매가 발생하지 않음
- Human-in-the-loop 구조를 명확히 보여줌
- 투자 조언이나 자동매매 서비스로 오해될 가능성을 줄임
- 리스크 관리와 설명 가능성을 우선한다는 설계 철학을 보여줌

## 현재 완성도

| 항목 | 상태 |
| --- | --- |
| 실행 가능한 MVP | 완료 |
| GitHub 포트폴리오 제출 | 1차 제출 가능 |
| 실제 매일 사용 | 가능하나 점수/리스크 기준 튜닝 필요 |
| 상용 서비스 수준 | 아님 |

Codex 없이 혼자 실행해야 할 때는 [최종 인수인계 가이드](final-handover-ko.md)를
먼저 확인하면 됩니다.
